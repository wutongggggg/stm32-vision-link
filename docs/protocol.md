# 协议说明（Vision-Link v1）

## 1. 帧格式

```
+--------+--------+-----+------+-----+---------------+-------+
| 0xAA   | 0x55   | LEN | TYPE | SEQ | PAYLOAD (LEN) | CRC8  |
+--------+--------+-----+------+-----+---------------+-------+
   帧头      帧头    1B    1B     1B      0..96B         1B
```

- 多字节整数一律 **小端（little-endian）**。
- `LEN` 只表示 PAYLOAD 的字节数，不含帧头/CRC。
- `CRC8` 多项式 `0x07`，初值 `0x00`，覆盖范围：`LEN + TYPE + SEQ + PAYLOAD`。

## 2. 消息类型

| TYPE | 名称 | 方向 | 说明 |
|---|---|---|---|
| 0x01 | DET | PC → STM32 | 一帧检测结果 |
| 0x02 | PING | PC → STM32 | 延迟测试，PAYLOAD 为任意 ≤16 字节 |
| 0x03 | PONG | STM32 → PC | 原样回传 PING 的 PAYLOAD |
| 0x04 | ACK | STM32 → PC | 预留：确认收到 DET（可选实现） |

## 3. DET 负载

```
frame_id(1) | n(1) | target[0] ... target[n-1]
```

每个 target 固定 10 字节：

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| +0 | cls | u8 | 类别 ID（0=person, 1=cup ... 由 PC 端映射） |
| +1 | conf | u8 | 置信度 ×100，0–100 |
| +2 | x | u16 | 左上角 x（像素） |
| +4 | y | u16 | 左上角 y（像素） |
| +6 | w | u16 | 宽（像素） |
| +8 | h | u16 | 高（像素） |

- `n` 最大 8；`LEN = 2 + 10*n`，最大 82。
- 坐标统一按 **1280×720 逻辑分辨率**发送（PC 端会把实际采集分辨率缩放到这个坐标系），STM32 只做比例映射。

## 4. 示例帧

1 个目标：`frame_id=1, cls=0, conf=0.90, x=320, y=240, w=100, h=80`，SEQ=7：

```
AA 55 0C 01 07 01 01 00 5A 40 01 F0 00 64 00 50 00 BA
```

> 该帧已用 PC 端 `protocol.py` 与 MCU 端 `protocol.c` 双向验证，输出逐字节一致（CRC=0xBA）。

## 5. 解析状态机

```
H1 --AA--> H2 --55--> LEN --(<=96)--> TYPE --> SEQ --> PAYLOAD --> CRC --> 回调
                \--其他--> H1        \--过长--> H1
```

- 任意阶段收到非法字节都回到 `H1` 重新找帧头。
- CRC 错误时丢弃整帧并回到 `H1`，不产生回调。
- STM32 端在 `protocol.c` 中实现，PC 端在 `protocol.py` 中实现（PC 主要用于收 PONG）。

## 6. 设计说明

1. **帧头 + 长度 + CRC**：实现帧同步、长度校验与误码检测；
2. **定长 target 结构**：解析无需动态内存，适应 20 KB RAM 的 MCU；
3. **PING/PONG**：提供可量化的链路往返延迟指标；
4. **计算分层**：PC 执行视觉计算，MCU 执行实时控制，符合端侧系统分工。
